# Product-aware reranking

Transparent equality rules compare explicit required specs, category and active status. Conflicts→incompatible, missing facts→insufficient information. Exact MPN never overrides a hard requirement. Complete declared category/spec agreement allows compatible alternatives; otherwise possible alternative. Approved JSON specs may include category.

This is extensible key-based equality, not comprehensive OEM/socket/electrical certification or unit conversion. Order:exact,compatible,possible,insufficient,incompatible; RRF within class. No cross-encoder/LLM judgment. Multiple exact variants yield ambiguity; no reliable candidate abstains. Only exact/compatible candidates can be selected. One decision per actor/run; a new search creates another decision opportunity.

A specified manufacturer is a hard requirement; an unmatched manufacturer cannot be labeled compatible merely from category/spec equality. Explicit reviewed aliases remain accepted.
