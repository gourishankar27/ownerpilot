# Evidence and historical compatibility

New records pin prompt `procurement-native/7`, planning `procurement-planning/2`, coverage `research-coverage/2`, tools `procurement-tools/3`, claims `research-citation-only/2` and verifier `research-verifier/3`, as well as model tag/digest, strategy, batch size and all finite limits. Resume compares these pins before invoking the provider.

Dispatcher behavior is additive: planning-policy-2 records use the new runner; citation-schema-2 records without that policy use the frozen Phase 3.1 runner; original records use legacy execution. Unknown planning policies stop safely. Frozen provider, v2 runner, original verifier and tool modules are unchanged. Historical prompt-5/6 evidence is not reinterpreted under new semantics.

Verifier 3 explicitly differs in two areas: physical batch-parent citation bindings, and unsuccessful uncited tool attempts. Such attempts are retained in `tool_failures` but provide no source coverage or citable fields. A later correct read can complete research. Referencing an unsuccessful receipt still fails. Verifier 2 retains its original treatment.

Scalar values are materialized from receipt data with exact types. UUID ownership, RFQ revision, source run, reviewed selection, product, catalog version, supplier offer, source fingerprint and semantic field association are checked. Null/zero/unknown are distinct. No source snapshot field substitutes for a missing executed read.

Migration 0008 adds run counters and coverage/planning JSON, and tool origin/details defaults. Existing receipt immutability protects the added fields. Populated upgrade checks compared original columns in 39 tables: 3,149 demo rows and 6,520 test rows were preserved exactly. Fresh migration and a second idempotent application passed; see `results/migration-preservation.json` and `results/fresh-migration.json`. Historical document blobs were copied to the isolated new root without changing their original bytes.

Before final browser/probe uploads, all 177 documents in the isolated demo clone were checked against stored sizes and SHA-256 fingerprints: zero missing or mismatched blobs (`results/blob-check.json`). This includes the 81 copied historical documents and 96 new frozen RFQ sources.

`results/preservation.json` records historical file hashes. Validation screenshots generated by unchanged old browser tests are archived separately and their frozen historical image paths restored byte-for-byte after the run. No old tests or assertions are weakened.
