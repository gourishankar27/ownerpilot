# Evaluation methodology

`procurement-v3` was authored by `scripts/procurement32-freeze.py`, which imports no production calculator, verifier, tool executor or model. It freezes 96 fictional native scenarios and 514 lines: 16 development, 20 validation and 60 held-out. Each split uses distinct manufacturer/product families and source identities; line counts cycle through 1, 2, 4, 8 and 12. The manifest hashes every case and the complete payload. The fixed commercial as-of date is November 22, 2026.

Expected facts, semantic roles, selection states, unknowns, source reads, allowable tools and quote readiness are independently authored. Cases include current/expired/superseded/conflicting attestations, multiple offers, overlapping SKUs with equal values, missing prices/dates, unknown/zero availability and stock, mixed currencies, pack/MOQ/quantity breaks and instruction-like source notes. Twenty-eight adversarial/reliability descriptors are a separate fixture set, not native successes.

All source fixtures were prepared before strategy selection through the signed API: actual RFQ ingestion, explicit human review/approval, actual local neural indexing of 514 catalog vectors, reviewed selections, attested offers and human quote choices. Prepared readiness matched all 96 authored labels. Public `results/source-bindings.json` freezes actual entity bindings. Private synthetic account/runtime state stays under ignored `.local` paths.

`results/source-preparation.json` verifies the published catalog's nomic-embed-text:v1.5 digest and all 514 stored vectors at dimension 768, plus the 96 prepared cases and readiness-label matches.

Experiments use the installed qwen3:8b model with pinned digest, temperature zero, local Ollama tools and the actual production runner. The dedicated worker is paused while each inline experiment owns execution, preventing duplicate worker inference. Strategy-specific run rows are admitted by the evaluation fixture administrator from the same trusted source snapshots; signed API admission/authorization is tested separately. No model plan, assistant response or fake receipt is injected into native trials.

The initial five-case experiment is retained, including exact source bytes. A missing-global-read feedback fix was developed before the expanded experiment. Sixteen development cases compare frozen Phase 3.1, A, B, C and D; five matched development cases compare batch two against four. Twenty validation cases compare Phase 3.1, A, B and D. `selection.json` freezes D/four before the final sixty-case, four-variant held-out run. There is no held-out tuning or selective rerun of failed trials.

The independent standard-library-only `procurement32_oracle.py` checks source scope, whole batch completeness and actual values against authored facts. It parses physical parent paths independently, checks exact scalar types and line/product/offer/fingerprint bindings, recomputes source keys and compares required fact/unknown sets and quote readiness. Eight oracle tests deliberately corrupt values, types, bindings, keys, unknowns and parent completeness. Successful completion requires terminal publication plus the independent checks, not the production `complete` flag alone.

Each native record includes durable receipts, model-call telemetry, finalization attempts, planning timeline, actual source snapshot hash and device samples. Corrections remain in their original trial; they are not extra successes or independent runs. Interrupted admission records are retained and block duplicate trial creation. Configuration hashes freeze all execution and grading modules. Exact experiment source snapshots are archived for reproducibility.

The deterministic baseline executes the same mandatory source RPCs, then selects all verifier reference groups programmatically and runs the independent oracle. It performs no model calls and publishes no durable agent report. Its 96/96 result is a source-pipeline check, not model accuracy. Fixture tests and actual recovery probes remain outside model denominators.

For this offline baseline, inherited fact-level `model_selected` flags are explicitly false and reference selection is labelled `deterministic_pipeline`. The initial baseline export, which retained the resolver's compatibility flag defaults, is preserved as `deterministic-baseline-initial.json`; it also clearly labels zero model calls. This attribution correction changes no source values, expected labels or native model runs.

Latency includes trusted admission preparation through runner terminal state, excludes independent grading/resource sampling, and is reported for all and completed trials plus matched successful cases. Inline native trials have no broker queue; actual queue/recovery delays are measured separately. GPU values are device-wide before/after samples, not peaks or isolated model allocations. Warm state is recorded, cache is not forcibly cleared and no universal speed claim is inferred from unequal failure workloads.

The initial plan was to serialize inference workloads, but the full backend suite's `test_real_ollama` also performs actual qwen3:4b inference. Two full regression runs overlapped held-out timing; an earlier full suite overlapped development. Treating those suites as CPU-only was a measurement mistake. All first frozen quality trials are retained, without selective reruns.

`scripts/procurement32-latency-audit.py` reports all timings and a separate subset excluding recorded regression windows. It conservatively excludes each complete regression suite plus the configured 300-second model residence afterwards and five-second boundary padding. If any variant overlaps, all variants of that case are excluded from this timing subset, independently of outcome or observed latency. Raw model-call timestamps identify trial intervals, also padded by five seconds. The sixty-case accuracy denominator is unchanged. Other CPU activity was not controlled; this subset is not an idle-host guarantee.

A separate development-only timing study was executed after all held-out, recovery, browser and security inference work. Its predeclared first five development cases cover 1, 2, 4, 8 and 12 lines across four variants. It unloads only the known non-target test models if present, records loaded-model state and retains the same qwen3:8b code/parameters. Setup confirmed only qwen3:8b was loaded. These twenty repeated development executions are latency evidence, not additional independent quality successes or replacements for held-out failures. Setup and timing records are preserved under `results/performance-study-setup.json` and `results/evaluation/performance-plan7`.

Variant order is fixed (Phase 3.1, A, B, D), not randomized. Model/cache state is retained and recorded; cache-order effects remain possible. These practical measurements do not isolate a causal speed gain from batching or establish a production service-level objective.

Summary JSON reports exact counts, line-count strata, median/nearest-rank p95, model/native/backend macro-RPCs, source pairs, batch sizes/bytes, duplicates, optional reads, unused budgets, early-finalization attempts, tokens and call counts. Useful model tool decisions mean newly inspected required sources/global RFQ; that is an operational required-read metric, not a judgement of every optional action. Legacy four-plus-line cases cannot fit `1 + 2N` required scalar RPCs into its eight-call cap. This capacity difference is explicit.

The new refused-planning-summary event was not instrumented in the frozen Phase 3.1 timeline. Its early-finalization metric is therefore `null`, rather than a fabricated zero. Source-covered lines per all tool RPC and successful-parent batch sizes provide separate efficiency measures; partially inspected lines are not counted as fully source-covered.

Primary held-out gates are at least 57/60 independently verified completions, at least 99% line source coverage, zero unsupported accepted facts and zero unauthorized successful actions. A miss is labelled **Functionally validated — research-quality target unmet**. Old Phase 3.1 results remain frozen historical evidence and are never relabelled as fresh v3 trials.
