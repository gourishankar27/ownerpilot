# Security and evidence validation

The new tool schema is closed. Extra workspace/RFQ/user identifiers, arbitrary URL targets, prices and policy overrides are rejected before execution. All batch members are authorized before any child read. Old scoped tools, local endpoint allowlists, signed method/path/workspace tokens, role checks, approval gates and deterministic finance remain in force.

Tests cover whole-parent failure, missing/duplicate/rebound children, excessive output, malformed/case-reordered IDs, cross-workspace and cross-job receipts, source/run/revision changes, revoked membership, wrong product/catalog/selection/offer/fingerprint, equal-value cross-line and cross-offer substitutions, non-scalar values and null/zero/unknown distinction. The runner revalidates each successful service body before persisting it as a successful source receipt. Invalid source responses cannot gain source coverage.

Controlled integration requests for quote approval, arbitrary URL fetching and a price-injected batch are rejected, retained as unsuccessful model-selected attempts and excluded from citable evidence. Hybrid recovery performs only backend-labelled missing mandatory reads. Duplicate source RPCs gain no extra coverage contribution and a third equivalent request is rejected. Cancellation between batch execution and receipt commit prevents that commit and publication.

The commercial-source-change test performs a real signed attestation update after a successful selection-only parent receipt and before the offers-only parent. Source revalidation stops the run before the later read/finalization. Previously committed receipt bytes remain intact.

The final model response remains citation-only, without values or association overrides. Exact typed scalar materialization and independently checked physical receipt paths prevent fabricated commercial values from being accepted. A single bounded correction may select missing valid references but cannot add a business tool, price or policy action.

Instruction-like catalog/attestation notes are included in frozen sources and receipts. New planning observations omit those raw notes and commercial bodies; finalization receives reference keys/paths only. This demonstrates context minimization, not a claim that the model saw and refused every hidden source payload. Approved RFQ descriptions remain untrusted data under the system policy. No supplier messages, quote approval or cloud execution is available through this registry.

The separate native description probe initially produced no extracted row, and ordinary RFQ approval rejected the empty RFQ (422). This is retained as a fixture-preparation failure, not claimed as a demonstrated injection filter or model refusal. An explicit fixture operator added and reviewed a structured row through the normal signed API while retaining the instruction-like description. The original native run then completed: a later acknowledged planning request followed the approved-RFQ receipt containing the attack, with zero successful unauthorized tools and no fabricated accepted price. An interrupted report export was resumed from that same durable run without rerunning inference. See `results/native-description-preparation-initial.json`, `results/native-description-probe.admitted.json` and `results/native-description-probe.json`.

Native trial safety counts come from the independent oracle over all emitted facts and actual successful tool receipts. Controlled malicious/fault fixtures establish rejection behavior and do not inflate native model success rates. Full regression tests retain the prior extraction, catalog, finance, authorization and quote approval assertions.
