# Reliability validation

Real integration evidence: results/final/real-workflows.json records signed localhost HTTP requests to FastAPI8011, PostgreSQL jobs, Redis6381 and the actual Linux worker. There is no fixture provider or in-process publication in this experiment. It covers a clean table with zero calls, digital PDF with five rows, scanned grid with five OCR-derived rows, partial-table selective routing and genuine qwen3:4b inference on five-item development prose.

The partial-table workflow preserved its reliable deterministic item and made one model call, but its added row contained no populated fields. The route ran correctly; item recovery failed. Do not use its row count as a successful repair claim. The real model prose run produced five items; per-field status still requires review. Unit tests with explicit authored proposals establish conservative repair mechanics, not model quality.

The same HTTP experiment verifies422 approval before review, a raw2→reviewed3 quantity correction, successful explicit approval,409 reprocessing of the approved version, and404 for another workspace's evidence and original document download. The original browser workflow exercises Better Auth and the signed Next proxy, persisted correction/approval and reload. Old regression tests retain role denial, stale revision checks, immutable history and atomic publication rollback.

The real restart experiment targeted only ownerpilot-rfq-phase11-worker-1 with Docker SIGKILL while a20-page synthetic raster PDF was parsing. It restarted that container, recovered on attempt2, published100 items with exactly one extraction run and revision1, and retained one run after three repeated deliveries. Policy was selective-v2, actual model calls0. Persisted queue wait was62550.867ms, including interrupted/recovery scheduling. It is not an ordinary steady-state latency measurement. See worker-restart.json and the guarded runtime-check script.

Cancellation fixtures persist cancellation during a selective provider call and immediately before publish; both prevent publication. Advisory-lock concurrency, duplicate delivery, stale revisions, database/broker failure, retry limits and transactional rollback remain covered by original tests. No HTTP disconnect is claimed to stop Ollama GPU generation. Cancellation is checked before calls and before publication; an in-flight request can finish and consume compute before the worker observes cancellation. A real SIGKILL during model generation was not separately measured; real recovery was during OCR.

Defaults are configurable within Pydantic bounds. Single Celery concurrency prevents this worker issuing parallel model calls; it does not globally serialize unrelated Ollama clients.

Image and document parsing run in the existing Linux container architecture. This is practical resource isolation, not hostile-file security certification. Public deployment still needs workload/queue quotas across users, sandbox/seccomp/network restrictions, malicious parser corpora, multi-worker scheduling/load tests, retention/backups and operational monitoring. Boundaries are unchanged; no public deployment was performed.
