# Selective hybrid extraction

The original policy bypassed model extraction for an entire document whenever any deterministic item existed. `phase1` retains that behavior through a checksummed frozen implementation. `selective-v2` first records deterministic rows, source anchors, recognized headers, candidate rows, consumed blocks and unresolved blocks.

Coverage is a heuristic over observable table candidates. Prose has an unknown denominator; the pipeline does not assert complete coverage from a confidence score. Header/page/worksheet transitions reset structural context. Candidate rows require an observable line number or description plus identifier/quantity. Unconsumed candidates, missing required fields, uncertain identifiers and procurement prose create tasks with reasons and source IDs.

Eligible tasks include their real table header and source block, deduplicated before bounded batching. Clean complete tables create no model calls. Literal quantity ranges and already structurally associated OCR-only ambiguity are recorded for human visual review rather than asking a language model to guess characters. The maximum is eight model batches per document,250 selected source blocks,12k input characters,40 chunks,8192 configured context and4096 output tokens in the selected run. Input bytes conservatively reserve context/output overhead; they are not presented as exact tokenizer counts. Provider retries are at most one retry in the selected configuration, within a30-minute job budget and single worker concurrency.

Model proposals pass closed Pydantic validation and exact block/excerpt checks before structural verification. Merge identity uses document-scoped source anchors. Reliable deterministic values remain; supported conflicts retain original values and review warnings. Same-source proposals merge or count as duplicates, while matching product identifiers from different rows remain distinct. Stable item IDs derive from source identity, not guessed products. There is no cross-row catalog deduplication.

Metadata records original/accepted deterministic rows, repaired/added rows, rejected unsupported values, conflicts, duplicate proposals and unresolved fields; source selection, routing reasons and merge decisions; actual calls and model/digest/prompt/config; parser/OCR/model durations; and escalation count zero. These are observations, not probability estimates.

Tests use explicitly named providers to inject valid repair, conflicts, failure and cancellation. They establish mechanics only. The real partial-table workflow selected the unresolved prose block and invoked Ollama, but the generated extra row was empty; it did not recover the item. The authored post-selection diagnostic records the resulting F1 regression. This limitation remains visible in [ablations](EXTRACTION_ABLATIONS.md) and [final results](EVALUATION_RESULTS.md).

Limitations: row continuation is not reconstructed into a sophisticated cross-page table graph; long-document chunk boundaries can separate headers from selected rows; prose label verification is conservative and can be incomplete; no90/180-degree OCR orientation support; repeated-header heuristics can misclassify unusual layouts. The OCR-only ambiguity bypass depends on evidence method identity and may not recognize OCR-derived fields whose extraction method is deterministic, so some uncertain scans still make model calls. A model can return a valid empty item. These remain unresolved for later work and were not tuned using final labels.
