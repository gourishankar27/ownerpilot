# Citation-only protocol

New runs pin `procurement-native/6`, `research-citation-only/2`, `research-verifier/2`, `procurement-tools/2`, model tag and actual digest. Historical prompt 5 contracts retain model-produced `value` and exact verification; they are never relabelled as citation-only runs.

The model returns only this closed structure:

```json
{"claims":[{"receipt_id":"00000000-0000-0000-0000-000000000001","source_key":"s0123456789ab","pointers":["/data/attestations/0/price"]}]}
```

`source_key` is generated by the backend from the receipt and trusted subject binding. It binds a group to one RFQ line/offer even when two sources contain equal prices. The model cannot set a product, offer, role, workspace, scalar value or final completion status. Extra fields, including `value`, reject the group. Unknown JSON members at the root, duplicate JSON keys and non-JSON constants reject the document. A sanitization checkpoint retains opaque rejection markers instead of copying prohibited model values or reasoning into storage.

Limits: 32 groups, 32 pointers per group, 300 characters per pointer and 64 KiB total provider response. The finalization inventory includes required references and subject identifiers but no commercial scalar values. Grouping reduces repeated receipt UUIDs; it does not execute tools or choose a supplier.

Pointers use JSON string representation with `/data` as the tool-wrapper root. Strict traversal supports `~1` and `~0`, preserves single-pass decoding of `~01`, and rejects invalid escapes, missing keys, scalar traversal, negative/leading-zero/non-ASCII array indices and array append `-`. Root/object/array references cannot become scalar facts. This follows the relevant traversal rules in [RFC 6901](https://www.rfc-editor.org/rfc/rfc6901.html); URI-fragment pointers are outside this application contract.

Ollama planning uses native `tools`; finalization uses a JSON Schema `format` and no tools. Token and duration telemetry comes from actual response fields documented by [Ollama](https://docs.ollama.com/api/chat). Schema-constrained generation still requires independent evidence verification.
