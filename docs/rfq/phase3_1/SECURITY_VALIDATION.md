# Evidence and action security

The original signed workspace proxy, authentication, membership authorization, closed read-only registry and quote approval rules remain in force. The new runner rechecks membership and source identity before protected operations and final publication. Neither final references nor a correction can mutate commercial sources, calculate an authoritative total through model prose, submit a quote or approve one.

New resolver fixtures cover RFC 6901 escapes/indices, scalar/object distinctions, nulls/zero, decimal strings, exact boolean/integer types, wrong run/workspace, failed receipts/schema, mismatched product/catalog/fingerprint/offer, equal-value cross-offer references, cross-line quantity references, fabricated pointers, numeric text in a source description, unsupported association overrides, duplicate JSON keys, strict forbidden `value`, semantic deduplication, missing coverage and valid partial evidence.

Runner integration fixtures use real PostgreSQL, signed API admission and explicit model protocol stubs. They exercise one successful correction, exhausted/disabled correction, cancellation during correction, prohibited correction-time tools, revoked membership, source mutation during inference, unknown protocol, model/prompt pin mismatch, idempotent terminal delivery and six controlled crash stages. They are **not native model benchmarks**. Original cross-workspace, upload/path, SSRF/local-provider, quote role and immutability cases remain in the unchanged old suite.

Native source/catalog/policy injection cases are part of the frozen larger benchmark. Actual tool receipts and independently checked facts, including failed cases, are retained. No raw model reasoning is saved. Non-reference prose/values in new final output are replaced by opaque rejection markers before durable finalization storage. Original legacy-protocol candidates remain separately labelled for historical diagnosis.

Commercial fields are trusted only in their declared source class. User-attested price/freshness remains a human attestation, not proof of a current supplier feed. Unknown stock or delivery remains unknown. Imported URLs/source text do not create a fetch capability. No network or operating-system tool was added.

Quantitative safety results and exact suite totals are in [validation](PHASE3_1_VALIDATION.md) and [evaluation](EVALUATION_RESULTS.md). Zero observed unsafe effects in synthetic tests is a measured scope-limited result; it is not a production security certification.
